# Тестовые сценарии для проверки функциональности

## 1. Тестирование сканирования QR-кодов

### Сценарий 1.1: Валидный чек
```bash
# Авторизация пользователя и получение токена
POST /auth/login
{
  "email": "user@x-pharm.rf",
  "password": "password"
}

# Сканирование валидного QR-кода
POST /fns/scan-qr
Headers: {
  "Authorization": "Bearer <token>",
  "Host": "x-pharm.checkpoint.rf"
}
{
  "fn": "1234567890",
  "fd": "123456", 
  "fp": "1234567890"
}

# Ожидаемый результат: статус "pending", requestId сгенерирован
```

### Сценарий 1.2: Поддельный чек
```bash
# Сканирование поддельного QR-кода (будет отклонен ФНС)
POST /fns/scan-qr
{
  "fn": "0000000000",
  "fd": "000000",
  "fp": "0000000000"
}

# Ожидаемый результат: статус "rejected", чек не создается в БД
```

### Сценарий 1.3: Повторное сканирование
```bash
# Повторное сканирование того же чека
POST /fns/scan-qr
{
  "fn": "1234567890",
  "fd": "123456",
  "fp": "1234567890"
}

# Ожидаемый результат: "Cashback already received for this receipt"
```

## 2. Тестирование ручного создания чеков

### Сценарий 2.1: Валидное создание администратором
```bash
# Авторизация администратора
POST /auth/login
{
  "username": "admin",
  "password": "admin_password"
}

# Создание чека вручную
POST /receipts/manual
Headers: {
  "Authorization": "Bearer <admin_token>"
}
{
  "date": "2024-08-11T14:30:00Z",
  "number": 12345,
  "price": 150000,
  "cashback": 1500,
  "address": "ул. Тестовая, д. 1",
  "customerId": 1,
  "promotionId": "x-pharm",
  "products": [
    {
      "productId": 1,
      "offerId": 1,
      "cashback": 500
    }
  ]
}

# Ожидаемый результат: чек создан успешно, кешбек начислен
```

### Сценарий 2.2: Ошибка валидации подсети
```bash
# Попытка добавить товар из другой подсети
POST /receipts/manual
{
  "promotionId": "x-pharm",
  "customerId": 1,
  "products": [
    {
      "productId": 999, // товар из подсети "r-pharm"
      "cashback": 100
    }
  ]
}

# Ожидаемый результат: ошибка "Товары из другой подсети не могут быть добавлены"
```

### Сценарий 2.3: Клиент из другой подсети
```bash
# Попытка создать чек для клиента из другой подсети
POST /receipts/manual
{
  "promotionId": "x-pharm",
  "customerId": 999, // клиент из подсети "r-pharm"
  "products": [...]
}

# Ожидаемый результат: ошибка валидации клиента
```

## 3. Тестирование кешбеков

### Сценарий 3.1: Просмотр статистики администратором
```bash
# Получение статистики за день для конкретной подсети
GET /cashback/stats/today?promotionId=x-pharm
Headers: {
  "Authorization": "Bearer <admin_token>"
}

# Ожидаемый результат: полная статистика по кешбекам
```

### Сценарий 3.2: Отмена кешбека
```bash
# Получение списка кешбеков за день
GET /cashback/history/today?promotionId=x-pharm

# Отмена конкретного кешбека
PUT /cashback/123/cancel
{
  "reason": "Тестовая отмена"
}

# Ожидаемый результат: кешбек отменен, бонусы списаны с клиента
```

### Сценарий 3.3: История кешбеков клиента
```bash
# Авторизация клиента
POST /auth/login
{
  "email": "customer@x-pharm.rf",
  "password": "password"
}

# Получение истории кешбеков
GET /cashback/customer/history
Headers: {
  "Authorization": "Bearer <customer_token>"
}

# Ожидаемый результат: список всех кешбеков клиента с детализацией
```

## 4. Тестирование ограничений доступа

### Сценарий 4.1: Доступ клиента к администраторским функциям
```bash
# Попытка клиента создать чек вручную
POST /receipts/manual
Headers: {
  "Authorization": "Bearer <customer_token>"
}

# Ожидаемый результат: 403 Forbidden
```

### Сценарий 4.2: Доступ к чужим кешбекам
```bash
# Попытка получить детали чужого кешбека
GET /cashback/details/999
Headers: {
  "Authorization": "Bearer <customer_token>"
}

# Ожидаемый результат: 404 Not Found (если кешбек не принадлежит клиенту)
```

## Проверочный список (Checklist)

### Базовая функциональность
- [ ] Сканирование валидного QR-кода создает чек и начисляет кешбек
- [ ] Поддельные чеки отклоняются и не создаются в БД
- [ ] Возвратные чеки не начисляют кешбек
- [ ] Повторное сканирование чека блокируется
- [ ] Ручное создание чеков администраторами работает

### Валидация подсетей
- [ ] Товары из другой подсети отклоняются при создании чека
- [ ] Акции из другой подсети отклоняются
- [ ] Клиенты из другой подсети не могут получить чек для чужой подсети
- [ ] Валидация работает как при автоматическом, так и при ручном создании

### Кешбеки
- [ ] Автоматический расчет кешбека на основе акций
- [ ] История кешбеков доступна клиентам и администраторам
- [ ] Отмена кешбеков администраторами работает корректно
- [ ] Статистика кешбеков отображается правильно
- [ ] Бонусы корректно начисляются и списываются

### Безопасность
- [ ] Права доступа соблюдаются (клиенты не могут выполнять админские функции)
- [ ] Клиенты видят только свои кешбеки
- [ ] Администраторы видят все кешбеки или только своей подсети (в зависимости от роли)
- [ ] Валидация данных работает корректно

### Производительность и стабильность
- [ ] API отвечает в разумные сроки
- [ ] Ошибки корректно обрабатываются и логируются
- [ ] Транзакции базы данных работают атомарно
- [ ] Система обрабатывает параллельные запросы
