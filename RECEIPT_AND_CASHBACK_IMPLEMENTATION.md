# Реализация логики создания чеков и начисления кешбеков

## Обзор

Данная реализация включает в себя полную логику создания чеков и начисления кешбеков согласно требованиям:

- ✅ Сканирование QR-кодов и валидация через ФНС
- ✅ Автоматическое создание чеков только для валидных (не поддельных, не возвратных) чеков
- ✅ Ручное создание чеков администраторами
- ✅ Валидация подсетей при создании чеков
- ✅ Автоматический расчет кешбека на основе акций
- ✅ Отслеживание истории кешбеков
- ✅ Возможность отмены кешбеков администраторами

## Основные компоненты

### 1. FnsService - Обработка QR-кодов и интеграция с ФНС

**Измененные методы:**
- `handleCheckResult()` - Добавлена проверка поддельных чеков. Поддельные чеки автоматически отклоняются и не создаются в БД.

**Ключевые особенности:**
- Поддельные чеки (`isFake = true`) отклоняются с соответствующим сообщением
- Возвратные чеки (`isReturn = true`) не обрабатываются
- Только валидные чеки покупки создаются в базе данных

### 2. ReceiptsService - Создание и валидация чеков

**Новые методы:**
- `validateProductsForPromotion()` - Валидация товаров и акций для подсети
- `createManual()` - Ручное создание чеков администраторами

**Доработанные методы:**
- `create()` - Добавлена полная валидация подсетей, клиентов и товаров

**Валидация включает:**
- Проверка существования промоакции
- Проверка принадлежности клиента к подсети
- Проверка принадлежности всех товаров к подсети
- Проверка принадлежности всех акций к подсети

### 3. ReceiptsController - API для работы с чеками

**Новые эндпоинты:**
- `POST /receipts/manual` - Ручное создание чеков (только для администраторов)

### 4. CashbackService - Управление кешбеками

**Существующие функции (уже реализованы):**
- Автоматический расчет кешбека на основе акций
- История кешбеков для клиентов и администраторов
- Отмена кешбеков администраторами
- Статистика кешбеков

### 5. CashbackController - API для управления кешбеками

**Существующие эндпоинты:**
- `GET /cashback/history/today` - История кешбеков за день
- `PUT /cashback/:id/cancel` - Отмена кешбека администратором
- `GET /cashback/customer/history` - История кешбеков клиента
- `GET /cashback/stats/today` - Статистика кешбеков

## Пользовательские сценарии

### 1. Сканирование QR-кода пользователем

```javascript
// Пример запроса
POST /fns/scan-qr
Headers: {
  "Authorization": "Bearer <user_token>",
  "Host": "x-pharm.checkpoint.rf"
}
Body: {
  "fn": "1234567890",
  "fd": "123456",
  "fp": "1234567890"
}

// Возможные ответы:
// Успешно поставлено в очередь
{
  "requestId": "uuid",
  "status": "pending",
  "message": "Receipt verification started",
  "network": "X-Фарм"
}

// Поддельный чек
{
  "requestId": null,
  "status": "rejected",
  "message": "Receipt is fake"
}

// Чек уже сканировался
{
  "requestId": null,
  "status": "rejected",
  "message": "Cashback already received for this receipt in this network"
}
```

### 2. Ручное создание чека администратором

```javascript
// Только для администраторов
POST /receipts/manual
Headers: {
  "Authorization": "Bearer <admin_token>"
}
Body: {
  "date": "2024-08-11T14:30:00Z",
  "number": 12345,
  "price": 150000, // в копейках
  "cashback": 1500,
  "status": "success",
  "address": "ул. Пушкина, д. 10",
  "customerId": 1,
  "promotionId": "x-pharm",
  "products": [
    {
      "productId": 1,
      "offerId": 1,
      "cashback": 500
    }
  ]
}

// Ошибка валидации подсети
{
  "error": "Товары из другой подсети не могут быть добавлены в чек для подсети x-pharm: Аспирин (ID: 123, подсеть: r-pharm)"
}
```

### 3. Просмотр статистики кешбеков

```javascript
// Для администраторов
GET /cashback/stats/today?promotionId=x-pharm

// Ответ
{
  "totalCashback": 50000,
  "totalTransactions": 25,
  "activeCashback": 48000,
  "cancelledCashback": 2000,
  "uniqueCustomers": 15,
  "topOffers": [
    {
      "offerId": 1,
      "totalCashback": 15000,
      "transactionCount": 8
    }
  ]
}
```

### 4. Отмена кешбека администратором

```javascript
PUT /cashback/123/cancel
Body: {
  "reason": "Дублирующий чек"
}

// Ответ
{
  "success": true,
  "refundedAmount": 1500,
  "message": "Кэшбек на сумму 1500 копеек успешно отменен"
}
```

## Безопасность и валидация

### Валидация подсетей
- Все товары в чеке должны принадлежать к той же подсети (promotionId)
- Все акции должны принадлежать к той же подсети
- Клиент должен принадлежать к той же подсети

### Предотвращение мошенничества
- Поддельные чеки автоматически отклоняются ФНС
- Возвратные чеки не начисляют кешбек
- Проверка повторного сканирования одного чека
- Проверка отрицательных сумм (индикатор возврата)

### Права доступа
- Только администраторы могут создавать чеки вручную
- Только администраторы могут отменять кешбеки
- Клиенты видят только свою историю кешбеков
- Компании видят кешбеки только своей подсети

## Схема базы данных

Используются существующие таблицы:
- `receipts` - чеки
- `receipt_products` - товары в чеках
- `cashbacks` - история кешбеков
- `cashback_items` - детализация кешбеков по товарам
- `fns_requests` - запросы к ФНС

## Логи и мониторинг

Все операции логируются с соответствующими уровнями:
- INFO - успешные операции
- WARN - отклоненные чеки, лимиты
- ERROR - ошибки обработки

Ключевые события:
- Создание чека через ФНС
- Создание чека администратором
- Начисление кешбека
- Отмена кешбека
- Ошибки валидации подсетей
